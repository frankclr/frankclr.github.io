Maven 没有一个像 GRADLE_USER_HOME 那样“一把梭”的官方环境变量
但你可以通过 MAVEN_USER_HOME + user.home + settings.xml 组合拳实现 完全可控

Maven 3.9.x 开始正式支持的 MAVEN_USER_HOME

对于3.9.x以前的版本,采用 wrapper 配置的方式

项目目录结构

.mvn/maven.config

  • Maven 3.3+(2015) 支持
  • 一行一个参数
  • 不用引号
  • 路径用 /（Windows 下也稳）
    • repo 路径尽可能写成相对路径
      • 项目可移动
      • CI / 本地一致
      • 不绑死某台机器

关于 toolchains.xml

toolchains 的真实作用

  • 让 Maven 在“插件执行阶段”，为“特定插件”选择一个 JDK
  • 典型对象：
    • maven-compiler-plugin
    • surefire
    • exec-maven-plugin
    • javadoc
    • 而不是 Maven Core 本身。

toolchains 的行为模型 (这是 Maven 对“多 JDK”的唯一官方支持方式)

  1. 在项目配置自己声明需要哪个版本， 这只能指定 JDK 17/25 等版本，不能指定 vender
    <maven.compiler.release>17</maven.compiler.release>

  2. 指定版本和 vender
    在 pom.xml 中设置如下, Maven 会查找 MAVEN_USER_HOME/toolchains.xml 或者~/.m2/toolchains.xml 中 vendor 为 graalvm 版本 25 的 JDK。
    如果找到了，就用那个来编译、测试等，否则报错

测试你的 toolchains 配置

mvn org.apache.maven.plugins:maven-toolchains-plugin:3.2.0:display-discovered-jdk-toolchains

目标 实现字段
区分 Liberica 与 GraalVM 用不同的
指定要用哪个 JDK 在 pom.xml 的 toolchains-plugin 配置中指定 version + vendor
多 JDK 环境共存 在 toolchains.xml 中列出所有 JDK（不同 vendor/version）
Maven 选择 JDK 通过匹配 与 pom.xml 中的要求

IDEA Debug Maven Goal Maven Maven JVM

只要 JVM 是 Maven 起的，构建定义就可以

  1. Maven「启动时用哪个 JDK」
    • 是在 POM 解析之前就已经决定的。
    • 不能在 pom.xml 里决定 Maven 自己用哪个 JDK。
  2. pom.xml 只能影响“编译用什么 JDK”，
    不能影响“Maven 进程本身用什么 JDK”。
  3. 多项目、多 JDK 是 Maven 的先天痛点，
    toolchains.xml 是“官方补丁”，但不是完美方案。
