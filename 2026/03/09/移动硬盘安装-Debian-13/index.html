可能出现问题的地方

只有三个常见风险：

GPU

桌面环境会受 GPU 影响,但服务器机器 没有 GUI 就没问题

GPU 桌面稳定性
Intel 很稳定
AMD 稳定
NVIDIA 偶尔坑

WiFi

不同机器 WiFi 芯片不同,Debian 12/13 默认 firmware 已经比较全。只要安装：firmware-linux

CPU microcode

不同 CPU：Intel,AMD; 只要安装 intel-microcode amd64-microcode，就没有问题

LVM

LVM(Logical Volume Manager,逻辑卷)，它解决一个问题：传统分区无法动态调整大小,可通过 lvextend -L +20G /dev/vg/root 命令从 VG 中保留的空闲空间（free space）来分配新的空间

  • 不是从其他 LV（如 home 或 docker）自动拿空间
  • 如果未来 free 空间用完了，但还想扩容，可以：
    • 添加新磁盘 → 创建 PV → 扩展 VG → 继续分配 LV。
    • 或者缩小其他 LV（不推荐,需备份！且 ext4 缩小前要先 umount 并检查）

安装

分区

  1. 在 对磁盘进行分区 界面，先对物理硬盘建立 EFI 和 LVM
  2. 进入 “配置逻辑卷管理器”，先 “创建卷组“,
    • 才有 “创建逻辑卷“、”删除卷组“、”扩展卷组“ 和 完成 等选项
  3. 创建了 逻辑卷，才有 “删除逻辑卷“ 选项
  4. 配置完 逻辑卷组 和 逻辑卷 后，回到 对磁盘进行分区 页面，会显示配置的所有 逻辑卷
    • 在这里要 设置 分区格式 和 挂载点
  5. 特别的, 如果想重建 LVM,需要在选择 配置逻辑卷管理器 后弹出的下面的对话框

    一旦逻辑卷管理器设置完成,就不允许再对包含逻辑卷的磁盘上的分区进行额外的改动。因此,在进行下一步操作之前,请您确认是否真的满意这些磁盘上当前的分区方案。
    保留现有的分区布局并配置 LVM 吗?`

    • 选择 “是”，以进入逻辑卷管理器，然后先删除所有的 “逻辑卷“,再删除 “逻辑卷组“ 才能对整个 LVM 重新分配
    • 选择 “否” 的话，会返回，从而无法更改。
  6. Linux 以前： 但有些情况下，安装器检测到 / 可启动，就直接把 /boot 放 /
    于是独立 /boot 分区被忽略
    • 如果系统已经正常启动，/boot 在 /，完全没问题。
      很多现代 Linux 甚至没有独立 /boot，独立 /boot 并不是必须，只要 /boot/efi 存在即可 没有独立的 /boot 分区，结构更简单，不容易出错
    • 也可以手动启用独立 /boot

安装系统

  1. 在安装完基本系统后，会提示 “不使用网络镜像站点，继续安装吗?”
    • 选择 “否” 以选择镜像站点，并且最好设置 HTTP代理信息
    • 否则，在安装的时候，会从 Debian 官网，而不是镜像站点，下载安全相关的组件，会很慢。
  2. 最后 “软件选择” 里，只选择 SSH Server 和 标准系统工具，不要选择 GNOME 等桌面环境
  3. 等安装好基本系统后，重启
    • 如果重启后进入系统进终端，屏幕一直高速闪烁(Debian 在某些 4K 显示器上常见的问题)
      内核 KMS（Kernel Mode Setting） 在 early boot 阶段选择了一个显卡/显示器不稳定的模式，结果 tty 控制台不断重绘 → 看起来像高速闪烁
      1. 先确认是否是 KMS 问题（最常见）,在 GRUB 菜单：
        1. 选中 Debian
        2. 按 e
        3. 找到这一行：linux /boot/vmlinuz-...
        4. 在最后加：nomodeset, 变成：linux ... nomodeset
        5. Ctrl + X/F10 启动
      2. 在 GRUB 固定分辨率

        1. 启动界面
          在 GRUB 菜单按 c 进入命令模式, 输入命令 videoinfo 会列出 Grub 支持的各种分辨率, 一般不要选 3840x2160, 选 1920x1080 最稳定。

        2. 进入终端系统后，配置 sudo vi /etc/default/grub, 然后执行 sudo update-grub

      3. 如果闪烁仍然存在，可能是 framebuffer 问题
        可以尝试：GRUB_GFXPAYLOAD_LINUX=text，让 Linux 直接使用 80x25 text mode
      4. 显卡问题
        1. 确认显卡型号
          lspci | grep VGA
        2. Intel/AMD，可以限制 KMS 分辨率

          • 编辑 sudo vi etc/default/grub，

            • GRUB_CMDLINE_LINUX_DEFAULT="video=1920x1080"
              • GRUB_CMDLINE_LINUX_DEFAULT 定义了在正常启动（非恢复模式）时传递给 Linux 内核的默认参数
              • 参数还可以为:
                • quiet: 减少启动过程中显示的详细日志信息，使系统启动过程更“安静”（即屏幕上输出的内容更少），通常只显示一个启动画面或简单的进度提示，而不是滚动的内核和系统服务日志
                • splash：配合图形启动画面（如 Plymouth）使用
                • nomodeset：禁用内核模式设置，常用于解决显卡驱动问题
                • acpi=off、noapic 等：用于解决硬件兼容性问题

          • 然后更新 sudo update-grub

        3. NVIDIA
          • Grub 的 linux ... 行追加 nomodeset，先启动。
          • 等进入系统后，安装 NVIDIA 驱动

USB SSD启动【必做】

因为 USB SSD 要在多台电脑启动，必须确认:

  • EFI、BOOT、ROOT 和 HOME 等分区都来自同一个 USB SSD,不要混到内置硬盘。尤其注意 EFI 分区
  • 尤其注意： Grub 必须安装在 USB SSD 的 EFI 分区。因为如果是在现有 Windows 系统的硬件上安装的 Debian，Grub 默认会安装到 Windows 的 EFI分区
  • 否则换电脑可能启动不了

特别的

    在 /etc/fstab 中
    1. LVM 通常设备名 /dev/debian-vg/home 已经比较稳定,因为 LVM 名称不会变,可以不使用 UUID
    2. 如果分区不是 LVM 的，必须使用 UUID

Linux 文件有三个时间

  • atime access time 读取时间
  • mtime modify time 修改时间
  • ctime change time 元数据变化

Linux 2.6.30 以前默认行为 atime， 每次读取都会更新，即 读文件 → 产生写操作，导致增加 SSD 写入

  • noatime 就是完全关闭 atime, 读文件 → 不写磁盘 这样写入最少
  • 但是一些软件可能依赖 atime，例如：mutt、tmpwatch、某些 backup 工具等(现在很少见)
  • 对于 /boot、/boot/efi 分区，读取极少，不需要开启 noatime
  • 对于其他数据分区(不包括 swap)，都应该加 noatime

Linux 2.6.30 以后[包含 2.6.30]默认 relatime。

  • 只有当 atime < mtime 或 超过 24 小时 才更新 atime。效果是99% 减少写入,兼容大多数软件

最合理的是 lazytime, Linux kernel 4.x 以后支持，适用于 ext4、ext2、ext3、XFS 等
lazytime 的作用 atime/mtime/ctime 先写内存(应用程序可见),延迟刷盘(最长可达 24 小时，或在 inode 被回收、fsync、系统 sync 时才写入),显著减少 SSD 写入,提升性能和寿命，尤其对频繁读取的小文件场景（如桌面环境）有益

对于 USB SSD

  • 启用 trim
    • 使用 ext4 加 discard,启用在线 TRIM(online discard)
      • 当文件被删除或块被释放时，文件系统立即通知 SSD 控制器：“这些 LBA（逻辑块地址）不再使用，可以内部擦除”
      • 依赖于 SSD 支持 ATA TRIM 命令（几乎所有现代 SSD 都支持）
      • 保持 SSD 长期性能稳定（避免写入放大）；无需手动执行 TRIM。
    • 或者 每周自动 TRIM sudo systemctl enable fstrim.timer
  • 设置 commit=60, ext4 每 60 秒 flush journal，减少写入次数
    • 生产数据库/关键服务，commit=60 风险过高，建议 commit=5 或默认

关于 TRIM

TRIM 是一种 ATA/NVMe 命令，允许操作系统告诉 SSD：“这些数据块已经删除，你可以内部回收它们”。

  • SSD 的写入机制要求先擦除再写入，而擦除只能按“块”进行；
  • 如果不 TRIM，SSD 不知道哪些块是“已删除”的，会保留旧数据，导致写入放大（Write Amplification）和性能下降；
  • TRIM 让 SSD 提前清理无效页，保持高性能和长寿命

discard vs fstrim.timer 区别与选择

特性 discard（挂载选项） fstrim.timer（定期 TRIM）
触发方式 实时：文件删除时立即发送 TRIM 批量：每天（默认）运行一次 fstrim 命令
粒度 精细（每个释放的块都通知） 粗略（扫描整个文件系统，批量 TRIM 未用块）
性能影响 可能有微小延迟（但现代 SSD 几乎无感） 集中在某一时段，可能短暂占用 I/O
安全性 对加密文件系统（如 LUKS）需谨慎（可能泄露使用模式） 更安全（可控制何时 TRIM）
适用场景 桌面、通用服务器（推荐现代系统使用） 服务器、加密卷、老旧 SSD
  • 现代 SSD + 非加密文件系统 → 推荐使用 discard，简单高效。
  • LUKS 加密卷 → 避免 discard（除非你明确启用 –allow-discards），改用 fstrim.timer。
  • 老旧 SSD 或不确定兼容性 → 使用 fstrim.timer 更稳妥。

关于 snapshot

LVM 本身就支持 snapshot，所以 完全可以实现 apt 升级前自动快照 + 回滚
不过体验不会像 Btrfs 那么优雅(Btrfs 可以在线回滚)

snapshot 的原理

LVM snapshot 是：COW (copy-on-write)
流程：snapshot 创建 -> root 写入变化 -> 旧数据复制到 snapshot
snapshot 只存变化数据

如果系统炸了先进入 rescue 模式 / live USB 进行回滚操作, 然后重启
APT 支持 hook，所以也能自动 snapshot

LVM

  • snapshot 空间耗尽会失效
  • snapshot 多了会变慢
  • rollback 需要 reboot

Btrfs 可以

  • 瞬间 snapshot
  • 无限 snapshot
  • 秒级 rollback
  • 几乎无性能损失

显卡

  1. 确认 apt 仓库地址包含 contrib、 non-free 和 non-free-firmware

  2. 编辑sudo vi /etc/modprobe.d/nvidia-wayland.conf

  3. 开启百分比缩放(fractional scaling,分数尺度)
    gsettings set org.gnome.mutter experimental-features "['scale-monitor-framebuffer']"
    175% 的缩放 因为 GNOME 的实现方式 是先 200% 渲染，再 downscale。在 NVIDIA + Wayland 会有两个问题

    • GPU 占用明显上升
    • 部分应用模糊

  4. 异常排查

    1. 确认 nvidia kernel module 正常
    2. 确认 /dev/nvidia0 存在
    3. nvidia-smi 正常
    4. 再看 gdm / wayland
    • 如果对应的 linux-headers-xxxx-amd64 不存在，DKMS 就无法编译模块
    • 升级过 kernel，或者用 backports， 这更容易导致 headers 没同步安装
    • USB SSD 启动系统 可能遇到：Secure Boot
      • 如果 Secure Boot 开启，nvidia module 会被 kernel 拒绝加载
        表现就是：

        modprobe nvidia
        Operation not permitted

    • backports, 就是把新版本软件移植回稳定版
      • Debian Project 的稳定版原则是：系统发布后 软件版本基本冻结，只修 安全和严重 bug
        但很多软件（例如 GPU 驱动、Mesa、Kernel）更新太快，所以提供 backports 仓库，形成 stable + 新版本软件
      • backports kernel 常见坑：
        • linux-image 升级了，linux-headers 没跟着升级，DKMS 编译失败

声卡

基本配置

Linux 音频系统有多层音量控制，即使 GNOME 音量拉到 100%，底层可能仍被限制。
Debian 13 已经默认集成了声卡驱动，但音量较小，可以使用 alsa-utils 进行调整

  • ALSA（Advanced Linux Sound Architecture）：底层驱动（snd_hda_intel）

  • PipeWire（Debian 13 GNOME 默认已切换到 PipeWire）

  • GNOME 控制中心 + pavucontrol：用于音量控制和设备管理

  • GNOME 默认不允许超过 100% 音量（防止爆音），但有些硬件需要 >100% 才能达到合理响度

  1. alsa-store 服务移除原因
    • 现代 Linux 音频栈以 PipeWire / PulseAudio 为核心，ALSA 被视为底层硬件接口。
    • ALSA 的“保存/恢复”机制被认为过时且与上层服务冲突。
    • Debian 官方倾向于让 桌面环境（如 GNOME）或音频服务管理音量状态，而非依赖 asound.state
  2. alsa-restore 在 Debian 13 中是“按需触发”的，不是靠 systemctl enable， alsa-restore 服务默认也无法 enable

通道说明与推荐设置（以后置音频口输出为例）

通道说明
通道名 作用说明 推荐设置
Master 主音量总控，影响所有模拟输出 拉到 90%~100%（避免爆音可留一点余量）
Headphone 控制耳机输出（包括前置面板） 如果你插的是后置接口，此项可设低或静音；
若插前置耳机孔，则需拉高（80%+）并取消静音
Speaker 控制内置扬声器或后置主声道输出 必须取消静音（按 M），拉到 90%~100%（这是后置喇叭的关键通道！）
PCM 数字音频流增益（影响播放软件输出） 建议 90%~100%，过高可能导致失真
Front 前置左右声道（即使你没接前置，也可能用于主输出） 取消静音，拉到 90%~100%（ALC897/1200 常将主输出映射至此）
  • 在 ALC897/1200 上，“Speaker” 和 “Front” 往往共同控制后置绿色音频口。
  • 如果只调 Master 而 Speaker/Front 被静音或音量很低，声音就会非常小！
典型场景配置建议

  1. 使用 后置绿色音频口 接有源音箱

  2. 使用 前置耳机孔

    插拔耳机时，系统应自动切换路由。若无反应，可能需在 BIOS 中启用 “Front Panel Detection”。

  3. 常见错误设置

  • Speaker 或 Front 被静音（显示 MM） → 声音极小或无声
  • 只调高 Master，其他通道很低 → 实际输出受限
  • PCM 设为 0% → 所有播放软件无声（但系统提示音可能仍响）
  • 音频输出模式不匹配（如误设为“环绕声”）
    • 如果你只接了 2.0 喇叭或耳机，但系统设为 5.1 输出，会导致声道分散、声音变小。

设置采样率、位深

  1. 设置所有应用（包括 Firefox、Spotify）都以 96kHz/24bit 运行（如果应用支持）。

    ~/.config/pipewire/pipewire.conf

  2. 确认当前实际采样率
