Hyper-V

Hyper-V 管理界面显示有一台虚拟机 A，但是无法运行，也无法删除
管理员 PowerShell 执行 Get-VM, 也报错

这通常是 Hyper-V 的配置数据库中残留了一条无效的虚拟机注册记录（例如：虚拟机文件被手动删除，但未通过 Hyper-V 管理器或 PowerShell 正确注销），导致 Hyper-V 无法加载该虚拟机，但又在列表中“记得它存在”

  1. 先尝试获取所有 VM 名称（跳过错误）,如果报错的那台没出现在列表里，说明它已无法被正常识别
    Get-VM -ErrorAction SilentlyContinue | Select-Object Name
  2. 查看 Hyper-V 虚拟机配置文件目录（关键），默认路径为：C:\ProgramData\Microsoft\Windows\Hyper-V\Virtual Machines\
    ProgramData 是隐藏文件夹，请在文件资源管理器中启用“显示隐藏项目”。
    在该目录下，你会看到很多 .xml 文件，文件名是 虚拟机的 GUID，每个 .xml 对应一个注册的虚拟机
  3. 查找“幽灵虚拟机”对应的 GUID
    1. 如果你还记得虚拟机名称，可以打开每个 .xml 文件（用记事本），查找 <Name>虚拟机名</Name>
    2. 或者，运行以下 PowerShell 脚本列出所有注册的 VM 名称和 GUID（包括损坏的）
  4. 删除对应的 .xml 文件
  5. 删除快照链接文件（.avhx / .avhd）和虚拟硬盘（.vhdx）[可选]
  6. 重启 Hyper-V 虚拟机管理服务
    Restart-Service vmms
