Java Maven Gradle

  2. 配置环境变量 JAVA_TOOL_OPTIONS
    JVM 在启动时会自动读取两个环境变量：JAVA_TOOL_OPTIONS 和 _JAVA_OPTIONS
    JVM 在 JNI_CreateJavaVM 阶段读取这个变量。 不仅 CLI 工具受影响，嵌入 JVM 的程序也会被影响，比如Kafka 等 Java 应用程序
    只要 JVM 启动，就会自动追加这些参数，相当于 java $JAVA_TOOL_OPTIONS yourArgs...
    启动时你会看到JVM 打印的提示: Picked up JAVA_TOOL_OPTIONS: -Dfile.encoding=UTF-8 ...，可能会导致：shell脚本解析失败或者CI工具解析失败
    很多 CI（Jenkins、GitHub Actions）也会继承：JAVA_TOOL_OPTIONS
    官方建议用途 JAVA_TOOL_OPTIONS 场景：Debug JVM,全局 GC 参数,Java agent,临时测试;
    不推荐场景: 永久系统配置->难排查; 编码配置->容易冲突
    JDK18+ 新引入的属性 -Dstdout.encoding=UTF-8和 -Dstderr.encoding=UTF-8 用来解决 Windows 控制台乱码。
    JDK内部属性 -Dsun.stdout.encoding 和 -Dsun.stderr.encoding,JDK21之后其实已经逐渐不用它们
    JVM 参数是后面的覆盖前面。在设置了JAVA_TOOL_OPTIONS 或者 _JAVA_OPTIONS后发现异常，要及时检查真实命令的参数顺序

  4. Maven

    1. 正常情况下，由上面的1和2，也应该正常工作
      额外还可以考虑
      • 配置环境变量 MAVEN_OPTS 和 MVND_JVM_ARGS 为 -Dfile.encoding=UTF-8
      • 项目新建 .mvn\jvm.config 和 .mvn\maven.config,内容都是下面的内容
        • .mvn\jvm.config 等价于：MAVEN_OPTS="这里的内容"
          • 它只影响：启动 Maven 进程本身的 JVM(org.apache.maven.cli.MavenCli)
          • 不会影响：
            • maven-surefire-plugin fork 出来的测试 JVM
            • IDEA 里点 ▶ 运行的那个 JVM
        • .mvn/maven.config 等价于：mvn <这里的内容>
          • 它只影响：启动 Maven 进程本身的 JVM(org.apache.maven.cli.MavenCli)
    2. mvn 和 mvnd 有 -l x.log(或者 --logfile x.log) 把构建日志打印到文件

  5. IntelliJ IDEA 在上面设置了 PowerShell 和 JAVA_TOOL_OPTIONS 后

    1. idea64.exe.vmoptions 配置 -Dfile.encoding=UTF-8
    2. 构建、执行、部署 -> 构建工具 -> Maven -> 运行程序 -> 虚拟机选项填写 -Dfile.encoding=UTF-8
      • 这是为了参数最小配置，才这么处理的。
        • 如果 JAVA_TOOL_OPTIONS 按照前面的配置，不包含 -Dfile.encoding=UTF-8
          • IntelliJ IDEA 在使用 Maven 构建的时候，会读取系统的 -Dfile.encoding=GBK,中文又要乱码。
          • 使用 Gradle 正常
        • 如果 JAVA_TOOL_OPTIONS 包含 -Dfile.encoding=UTF-8, 影响又太大；
      • 也可以考虑设置 MAVEN_OPTS 环境变量
    3. IntelliJ IDEA 需要重启才能读取环境变量等配置
    4. 如果还有问题，就把其他编码全部加上

  6. CMD

    1. 特别注意 Windows 的 CodePage, 命令 chcp 65001
    2. 正常情况下，在上面配置了 JAVA_TOOL_OPTIONS 和 Gradle + Maven 相关配置后，也应该正常了

  7. Windows 上命令行永远可能乱码，唯一可靠的方式是输出到文件 + 统一 JVM /插件 UTF-8 编码，IDEA / CI 上直接看英文报错。

  8. 修改系统的编码为 UTF-8 ,Windows 10和Windows 11支持。
    此方法最为彻底，方便！但影响大量不支持UTF-8的程序;
    修改路径: 设置->时间和语言->管理语言设置->非 Unicode程序的语言->更改系统区域设置->勾选Beta版: 使用Unicode UTF-8 提供全球语言支持->确定
