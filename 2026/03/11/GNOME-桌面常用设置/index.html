桌面语言优化

因为系统如果设置了 中文 语言(zh_CN.UTF-8)

  • 会导致个人 ~ 下的目录是中文名的，这对于终端操作不友好
  • 会导致软件信息是中文的，可能使用英语更好命令操作
    • 比如 apt list | grep installed 操作失败，因为提示信息是 已安装，而切换输入法比较麻烦

Linux 下程序的语言由环境变量 LANG、LANGUAGE、LC_ALL 等控制。可以只为特定命令设置英文环境，不影响其他部分。

  • LANG=zh_CN.UTF-8 → 全局中文（包括终端命令输出）
  • LANG=C → 所有 locale 类别回退到 C（即英文 + 默认行为）
  • LC_MESSAGES=C → 仅“程序消息”用 POSIX 英文

建立自己的工具目录

把自己的工具脚本放到这里，方便使用，也不影响 bash 加载速度

创建快捷方式

应用程序

  • 最后，一定要右键 .desktop 文件 -> 允许执行，手动“信任”
  • .desktop 文件本身不需要可执行(rwx 的 x)
  • .desktop 文件 可以从 /etc/xdg/autostart/ 或 /usr/share/applications/（已安装应用的 .desktop 文件）复制
  • 即使启用了 DING，从 /usr/share/applications/ 拷贝过来的 .desktop 文件默认是“未信任”的，出于安全原因不会显示为可执行图标（可能显示为文本文件或根本不显示）
  • 要注意 语言 设置导致的 桌面 真实路径差异, $(xdg-user-dir DESKTOP) 确认

对于 .desktop 文件可能需要增加权限或属性

脚本的桌面图标

拷贝一个现有的 .desktop 文件，替换掉 Exec 的路径就好，但要注意 Exec 指向的脚本 myscript.sh 可能需要赋予可执行权限
chmod +x /home/yourname/bin/myscript.sh

第三方工具

第三方工具如 gnome-tweaks（优化工具） 也集成了部分启动项管理功能
gnome-tweaks & -> 开机启动程序 -> 添加应用

使用 systemd –user

Linux 现代发行版普遍使用 systemd，你可以为当前用户创建 用户级 systemd 服务，实现更精细的控制
这类服务也会在用户登录时自动启动（需确保 systemd --user 实例随会话启动，现代 GNOME 默认支持）

软件

dpkg 命令

对于 Debian, 有大量的 .deb 软件包，推荐使用 apt install ./xxx.deb
它会：

  • 将 .deb 复制到 /var/cache/apt/archives/
  • 自动计算并安装缺失依赖（从配置的仓库）
  • 调用 dpkg 完成实际安装
  • 避免“依赖地狱”，操作原子性更强（失败时回滚更安全）
