容器内的 localhost 解析优先级问题

容器内的 localhost 解析优先级问题，在 Podman（尤其是 rootless 模式）中表现得更明显。

localhost 在容器内如何解析？

在 Linux 容器中，localhost 的解析由 /etc/hosts 文件和 glibc 的解析器配置共同决定。默认情况下，/etc/hosts 中通常包含：

因此，localhost 会同时解析到 IPv4 地址 127.0.0.1 和 IPv6 地址 ::1。
关键点：glibc 的解析器（getaddrinfo）会按 /etc/nsswitch.conf 中定义的顺序查询主机名，通常先查 /etc/hosts，再查 DNS。当 localhost 既有 IPv4 又有 IPv6 记录时，解析器会返回两个地址，且默认优先返回 IPv6 地址（如果系统开启了 IPv6 支持）。

为什么在 Podman 中更容易出现这个问题？

Podman rootless 模式的网络隔离
Podman 默认以 rootless 模式运行，容器网络通过 slirp4netns 实现。在这种模式下，容器内的 localhost 实际上是容器自身的环回接口，与宿主机无关。但是，由于 rootless 模式的限制，IPv6 环回可能在容器内不可用或配置不完整，导致 ::1 连接失败。

Pod 共享网络栈的特殊性
虽然两个容器在同一个 Pod 中共享网络命名空间，但容器内的 /etc/hosts 仍是各自独立的。如果某个容器（如 mongo-express）的 /etc/hosts 中 localhost 同时有 IPv4 和 IPv6 条目，它仍会尝试 IPv6 优先，而 MongoDB 可能没有在 IPv6 上监听。

MongoDB 镜像的默认行为
MongoDB 官方镜像默认监听 0.0.0.0（所有 IPv4 地址），但不会自动监听 IPv6 的 ::。除非显式使用 –bind_ip_all 或配置 bindIp: ::,0.0.0.0，否则它只接受 IPv4 连接。
