基本设置

生成 ssh_key

  • Visual Studio 使用密钥远程登录，加密方法有限制
  • github 的密钥也有较强的限制
  • gitee/github/Visual Studio 都支持 ed25519 类型的密钥

编辑~\.ssh\config,配置ssh

将生成的 id_ed25519_all.pub 内容添加到 github 网站的 ssh 设置里。
如果是登录Debian 等 Linux 系统，需要将 id_ed25519_all.pub 内容添加到 ~/.ssh/authorized_keys 文件中。

要注意Host和HostName设置：

  • HostName只能是网站的域名,如果github.com

  • Host一般也设置为网站域名，如github.com,这样在git操作的时候，能与官方给的 ssh地址(如git@github.com:username/repo.git)保持一致，方便。

    测试

  • 也可以自定义设置，如设置为github或者1.github.com,但这个时候，官方给的ssh地址，需要调整为

    使用ssh -T验证的时候，也要使用Host里设置github进行验证。

可能出现的错误

  1. 权限错误

    • 重装系统后、不同系统拷贝等导致的权限错误问题
    • 不要将 .ssh 目录放在 OneDrive、Dropbox 或其他同步目录中（可能导致权限重置）

  2. ~\ssh\ 相关文件权限规则

    • 文件是否只被当前用户访问（不能被其他用户或组读取/写入）
    • 文件不能有“继承权限”或“Everyone / Users”等宽泛权限
    • 如果 私钥 或 config 被 “Users”、“Authenticated Users”、“Everyone” 等组拥有读权限，SSH 会直接拒绝使用，并报错Permissions for '...' are too open
    • 推荐权限设置
      文件/目录 所需权限
      .ssh 目录 仅当前用户完全控制
      config 仅当前用户读写
      myKey（私钥） 仅当前用户读写（最关键！）
      myKey.pub 可放宽，但建议同上

  3. 正确设置权限

    %USERNAME% 是当前登录用户的环境变量，通常可用。如果不行，手动替换为 YourName 或 YourPC\YourName

补充说明

  1. Windows 上 BUILTIN\Users 是一个用户组，默认包含所有本地用户。如果 SSH 私钥对这个组开放，OpenSSH 会认为不安全，从而报错
  2. 在 Linux/macOS 上同类错误通常表现为 Permissions 0644 for 'xxx' are too open，解决方法是 chmod 600 your_key
  3. ssh 设置代理麻烦，对于 github 就使用http协议进行操作
